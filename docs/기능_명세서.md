# WMS 기능 명세서

- 버전: 1.0
- 갱신일: 2026-09-23
- 제품: SmartStock AI Warehouse Management System

## 1. 목적

WMS는 창고 재고, 구역, 배송, 비전 모니터링을 하나의 웹 화면에서 관리한다. 사용자는 역할과 승인 상태에 따라 업무 화면에 접근하며, 모든 핵심 데이터는 PostgreSQL에 저장되고 Rust API가 처리한다.

## 2. 사용자와 역할

| 역할 | 설명 | 초기 상태 |
|---|---|---|
| 서버 관리자 | 시스템 전체 관리자. 관리자 가입 승인과 계정 관리를 담당한다. | `APPROVED` |
| 관리자 | 특정 창고의 운영 관리자. 창고지기 승인, 구역/품목/배송/비전 데이터 관리를 담당한다. | `PENDING_ADMIN` |
| 창고지기 | 현장 재고 및 바코드 업무 담당자. 담당 관리자 승인 후 창고에 접근한다. | `PENDING_WAREHOUSE` |

### 승인 규칙

1. 관리자가 회원가입하면 서버 관리자 승인 전까지 관리자 화면을 사용할 수 없다.
2. 서버 관리자가 승인하면 관리자 전용 창고가 생성되고 계정이 `APPROVED`가 된다.
3. 창고지기가 가입하면 담당 관리자 이메일을 등록해야 한다.
4. 관리자가 승인하면 창고지기의 `warehouseId`가 관리자의 창고로 설정된다.
5. 승인 전 사용자는 로그인할 수 있지만, `AuthGuard`가 업무 화면 접근을 제한한다.

## 3. 애플리케이션 라우트

| 라우트 | 기능 | 접근 권한 |
|---|---|---|
| `/` | 대시보드, KPI, 창고 현황 | 로그인 필요 |
| `/login` | 로그인 | 공개 |
| `/signup` | 회원가입 | 공개 |
| `/barcode` | 바코드/카메라 조회 및 재고 조정 | 로그인 필요 |
| `/delivery` | 배송 등록 및 상태 관리 | 로그인 필요 |
| `/monitor` | 카메라 이미지 분석 및 모니터 이력 | 로그인 필요 |
| `/report` | 재고 및 수요 리포트 | 로그인 필요 |

## 4. 기능 요구사항

### FR-01 로그인

- 사용자가 아이디/이메일과 비밀번호를 입력한다.
- `POST /api/users`를 `action=login`으로 호출한다.
- 성공 응답은 브라우저 local storage의 `wms_auth_user`에 저장된다.
- 잘못된 자격증명은 오류를 표시하고 로컬 로그인 상태를 생성하지 않는다.

### FR-02 관리자 가입 및 승인

- `관리자` 역할로 가입하면 `PENDING_ADMIN` 상태가 된다.
- 서버 관리자가 요청을 승인(`approve_admin`)하면 창고가 생성되고 해당 관리자에게 배정된다.

### FR-03 창고지기 가입 및 승인

- `창고지기` 역할로 가입하려면 `adminEmail`이 필요하며 `PENDING_WAREHOUSE` 상태가 된다.
- 관리자가 창고지기를 승인(`approve_user`)하면 관리자의 창고에 배정된다.

### FR-04 대시보드 및 재고 상태

- `shortage`: 현재 재고가 안전재고의 50% 미만
- `safe`: 현재 재고가 안전재고의 50%~200% 사이
- `overstock`: 현재 재고가 안전재고의 200% 초과
- 각 품목에는 부족/초과 수치 텍스트와 운영자 권고사항이 포함된다.

### FR-05 재고 관리

- 창고별로 재고 항목을 조회·생성·수정·삭제한다.
- 음수 현재 재고 또는 안전재고 값은 거부된다.
- 수정 시 상태, 라벨, 차이값, 권고사항을 다시 계산한다.

### FR-06 바코드 업무 흐름

- 카메라/스캐너 기반으로 창고 품목을 조회한다.
- 현재/안전 재고와 상태를 표시한다.
- 재고 API를 통해 입출고 수량 변경을 적용한다.
- 선택된 창고 컨텍스트를 유지해야 한다.

### FR-07 창고 구역 관리

- 선택된 창고의 구역을 조회·생성/수정·삭제한다.
- 구역 식별자는 창고 내에서 `(warehouseId, id)`로 유일해야 한다.

### FR-08 비전 레퍼런스 데이터

- 관리자는 AI 비교용 레퍼런스 이미지와 품목명을 창고 단위로 등록한다.
- 사용자는 레퍼런스를 조회하고 삭제할 수 있다.
- 다음 AI 분석 요청 시 최근 레퍼런스 최대 3개가 함께 전송되며, 품목명이 정확히 일치하는 레퍼런스를 우선 사용한다.
- 이는 레퍼런스 기반 추론이며, Groq 모델을 파인튜닝하거나 영구적으로 재학습시키지 않는다.

### FR-09 AI 모니터링

- 모니터 화면에서 카메라/이미지 프레임을 `POST /api/monitor`로 전송한다.
- Rust API가 이미지, 프롬프트, 창고 레퍼런스 이미지를 Groq Vision으로 전송한다.
- 결과(품목명, 추정 수량, 단위, 상태, 신뢰도, 권고, 판단 근거)는 `monitor_logs`에 저장된다.
- 창고·품목명이 일치하는 재고 항목이 갱신된다.
- `GROQ_API_KEY` 미설정 시 `503`, 외부 제공자/파싱 실패 시 `502`를 반환한다. 저장에 실패했는데 저장되었다고 화면에 표시해서는 안 된다.

### FR-10 배송 관리

- 운송장 번호(숫자만 정규화)로 배송을 등록한다.
- `AT_PICKUP` / `상품인수` 상태로 시작한다.
- 이동 중, 배달 출발, 배송 완료 상태로 순차 전이한다.
- 배송 완료 후 24시간이 지난 건은 목록에서 제외된다.

### FR-11 리포트

- 리포트 화면은 현재 보유한 재고 데이터를 기준으로 재고 위험 정보를 표시한다.
- 계산된 값과 AI 생성 권고를 구분해서 표시해야 하며, 데이터가 없을 때는 빈 상태를 보여줘야 한다.

## 5. 데이터 및 정합성 규칙

- 모든 재고 항목, 구역, 레퍼런스, 모니터 로그는 창고에 소속된다.
- 창고 삭제 시 `inventory_items`, `warehouse_zones`, `item_references`, `monitor_logs`가 함께 삭제(cascade)된다.
- 창고지기의 `warehouse_id`는 nullable이며, 창고 삭제 시 사용자는 삭제되지 않고 null로 설정된다.
- 기본 로컬 창고는 `wh_wjmals`이다.
- Rust 회원가입 흐름에서 생성되는 비밀번호는 Argon2 해시다.

## 6. 비기능 요구사항

### 보안

- 비밀번호는 어떤 API 응답에도 로그되거나 반환되어서는 안 된다.
- 운영 환경에서는 모든 변경성 API에 서버 측 인증/인가를 추가해야 한다.
- 내장 서버 관리자 자격증명은 소스 코드가 아닌 시크릿 기반 해시 계정으로 옮겨야 한다.
- 초대 흐름의 기본 창고지기 비밀번호(`123456`)는 일회성 활성화 또는 재설정 방식으로 교체해야 한다.
- 운영 배포 전 현재의 permissive CORS 설정을 제한해야 한다.

### 성능

- 재고 목록 조회는 `warehouse_id` 기준으로 인덱싱되어 있다.
- 모니터 이력은 요청당 50건으로 제한된다.
- 비전 레퍼런스 이미지 저장은 요청당 최대 50,000자로 제한된다.

## 7. 운영 흐름

### 신규 관리자

```text
관리자로 가입 -> PENDING_ADMIN -> 서버 관리자 approve_admin -> 창고 생성 -> 관리자 접근 활성화
```

### 신규 창고지기

```text
adminEmail 포함 창고지기 가입 -> PENDING_WAREHOUSE -> 관리자 approve_user -> 창고 배정 -> 창고지기 접근 활성화
```

### 재고 조정

```text
바코드/재고 화면 -> POST/PATCH /api/inventory -> 상태 재계산 -> 대시보드/리포트 갱신
```

### AI 모니터링

```text
이미지 캡처 -> POST /api/monitor (창고 레퍼런스 이미지 최대 3개 포함) -> Groq Vision 분석 -> 모니터 로그 저장 -> 일치하는 재고 갱신
```

## 8. 인수 테스트 체크리스트

- [ ] PostgreSQL이 연결되고 `/health`가 `database: configured`를 반환한다.
- [ ] 서버 관리자가 로그인할 수 있다.
- [ ] 관리자 가입이 `PENDING_ADMIN`을 생성하고, 서버 승인 시 창고가 생성되어 접근이 활성화된다.
- [ ] 창고지기 가입에는 `adminEmail`이 필요하며 `PENDING_WAREHOUSE`가 생성되고, 관리자 승인 시 창고가 배정된다.
- [ ] 재고 생성/조회/수정/삭제가 창고 기준으로 동작한다.
- [ ] 구역 생성/수정/조회/삭제가 동작한다.
- [ ] 비전 레퍼런스 생성/조회/삭제가 동작하며, 해당 창고의 분석에만 사용된다.
- [ ] 배송 등록/조회/상태 전이/삭제가 동작한다.
- [ ] 모니터 목록이 동작하며, `GROQ_API_KEY`가 설정되고 계정이 해당 Groq 모델에 접근 권한이 있을 때 AI 분석이 동작한다.
- [ ] 보호된 라우트는 비로그인 사용자를 `/login`으로 리다이렉트한다.
- [ ] 통합 테스트 후 임시 테스트 계정과 데이터를 삭제한다.
