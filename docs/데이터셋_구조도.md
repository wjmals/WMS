# WMS 데이터셋 구조도

- 대상: PostgreSQL 16에 저장되는 실제 런타임 데이터 구조
- 관련 문서: 테이블 관계는 `docs/DB_구조도.md`, API 계약은 `docs/API_명세서.md` 참고
- 현재 저장소에는 Firestore, 로컬 JSON 등 별도 데이터셋이 없다. 모든 데이터는 PostgreSQL 하나로 저장된다.

## 1. 시드(초기) 데이터

`rust-backend/schema.sql`이 최초 실행될 때 다음 한 행만 자동 삽입된다.

```sql
INSERT INTO warehouses (id, name)
VALUES ('wh_wjmals', 'WMS 기본 창고')
ON CONFLICT (id) DO NOTHING;
```

| 필드 | 값 |
|---|---|
| id | `wh_wjmals` |
| name | `WMS 기본 창고` |

그 외 `users`, `inventory_items`, `warehouse_zones`, `item_references`, `monitor_logs`, `delivery_tracking`은 초기 데이터 없이 빈 테이블로 시작한다.

## 2. 엔터티별 데이터셋 구조

### 2.1 users

```json
{
  "id": "3f2b6d3a-2c9a-4e2a-9e2a-6d2a3f2b6d3a",
  "username": "manager1",
  "email": "manager1@example.com",
  "name": "Warehouse Manager",
  "role": "관리자",
  "status": "APPROVED",
  "warehouseId": "wh_manager1",
  "adminEmail": null,
  "requestedAdminEmail": null,
  "createdAt": "2026-09-23T00:00:00Z",
  "approvedAt": "2026-09-23T00:10:00Z"
}
```

값 범위:

- `role`: `서버 관리자`(하드코딩, DB 미저장) | `관리자` | `창고지기`
- `status`: `PENDING_ADMIN` | `PENDING_WAREHOUSE` | `APPROVED`
- `password_hash`: API 응답에는 포함되지 않음(Argon2 해시로만 DB에 저장)

### 2.2 inventory_items

```json
{
  "id": "b1a2c3d4-....",
  "warehouseId": "wh_wjmals",
  "name": "고등어(가공)",
  "current": 3500,
  "safe": 10000,
  "status": "shortage",
  "statusLabel": "재고 부족",
  "diffText": "부족분: -6500톤",
  "recommendation": "재고 하한선 이탈 -> 즉시 추가 발주 필요",
  "cycle": "월간",
  "date": null,
  "createdAt": "2026-09-23T00:00:00Z",
  "updatedAt": "2026-09-23T00:00:00Z"
}
```

값 범위:

- `status`: `shortage`(`current < safe*0.5`) | `safe`(`safe*0.5 ~ safe*2.0`) | `overstock`(`current > safe*2.0`)
- `current`, `safe`: 0 이상 정수

### 2.3 warehouse_zones

```json
{
  "id": "A-01",
  "warehouseId": "wh_wjmals",
  "name": "냉동 보관 A-01",
  "state": "normal",
  "stateLabel": "정상",
  "temp": "-20°C",
  "items": [],
  "capacity": 100000,
  "updatedAt": "2026-09-23T00:00:00Z"
}
```

`items`는 JSONB 배열로, 구역에 배치된 품목 메타데이터를 자유 형식으로 담는다(고정 스키마 없음).

### 2.4 item_references (AI 분석용 레퍼런스 이미지)

```json
{
  "id": "c4d5e6f7-....",
  "warehouseId": "wh_wjmals",
  "name": "고등어(가공)",
  "description": "은색 비늘, 냉동 박스 포장",
  "thumbnail": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQAAAQABAAD...",
  "createdAt": "2026-09-23T00:00:00Z"
}
```

- `thumbnail`: base64 인코딩 문자열, 최대 50,000자로 서버에서 잘라 저장
- 창고별로 분리 저장되며, AI 분석 시 해당 창고의 레퍼런스만 최대 3개 사용

### 2.5 monitor_logs (AI 분석 결과 이력)

```json
{
  "id": "d5e6f7a8-....",
  "warehouse_id": "wh_wjmals",
  "camera_url": "webcam",
  "item_name": "고등어(가공)",
  "status": "safe",
  "status_label": "안전 재고",
  "estimated_quantity": 8200,
  "unit": "개",
  "confidence": 82,
  "recommendation": "현 유통 계획 유지",
  "reason": "박스 적재량이 안전 기준 범위 내로 관찰됨",
  "image_snapshot": "data:image/jpeg;base64,/9j/4AAQSkZJRgABAQ...(최대 1000자)",
  "analyzed_at": "2026-09-23T00:00:00Z"
}
```

- `image_snapshot`: base64 문자열의 앞부분만 최대 1,000자 저장(전체 이미지 보관용이 아님)
- `confidence`: 0~100 정수

### 2.6 delivery_tracking

```json
{
  "id": "e6f7a8b9-....",
  "invoice_no": "1234567890",
  "carrier_code": "04",
  "carrier_name": "CJ대한통운",
  "item_name": "물류 출고건",
  "sender_name": "WMS 스마트 물류센터",
  "receiver_name": "고객님",
  "status": "상품인수",
  "status_code": "AT_PICKUP",
  "current_location": "배송 접수처",
  "delivered_at": null,
  "tracking_details": [],
  "created_at": "2026-09-23T00:00:00Z",
  "updated_at": "2026-09-23T00:00:00Z"
}
```

값 범위(`status_code` 전이 순서): `AT_PICKUP` → `IN_TRANSIT` → `OUT_FOR_DELIVERY` → `DELIVERED`

### 2.7 warehouse_access_requests

```json
{
  "id": "f7a8b9c0-....",
  "userEmail": "worker1@example.com",
  "userName": "Worker One",
  "requestedAt": "2026-09-23T00:00:00Z"
}
```

## 3. 이미지 데이터 인코딩 규칙

| 위치 | 컬럼 | 인코딩 | 크기 제한 | 용도 |
|---|---|---|---|---|
| `item_references` | `thumbnail` | base64 (`data:image/...;base64,...`) | 최대 50,000자 | AI 분석 시 참고 이미지 |
| `monitor_logs` | `image_snapshot` | base64 앞부분만 저장 | 최대 1,000자 | 분석 이력 확인용 스냅샷 |

두 컬럼 모두 파일이 아니라 텍스트 컬럼에 문자열로 저장된다.

## 4. 창고 간 데이터 분리 규칙

- `inventory_items`, `warehouse_zones`, `item_references`, `monitor_logs`는 모두 `warehouse_id`로 구분된다.
- 조회 시 `warehouseId` 쿼리 파라미터가 없으면 기본값 `wh_wjmals`를 사용한다.
- `delivery_tracking`은 창고로 구분하지 않는 시스템 전역 데이터셋이다.

## 5. 현재 데이터셋의 한계

- 실제 운영/현장 데이터가 아직 없어 위 예시는 필드 구조를 보여주기 위한 샘플이다.
- `warehouse_zones.items`, `delivery_tracking.tracking_details`는 고정 스키마가 없는 JSONB이므로 프런트엔드와 합의된 형식을 별도로 유지해야 한다.
- 이미지 데이터는 텍스트 컬럼에 저장되므로, 데이터량이 많아지면 별도 오브젝트 스토리지 전환을 검토해야 한다.
