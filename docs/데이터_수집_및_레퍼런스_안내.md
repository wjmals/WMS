# 데이터 수집 및 레퍼런스 등록 안내

이 안내서는 현재 구현된 비전 레퍼런스 수집과 엑셀 일괄 등록 절차를 설명한다. 여기서 "학습 데이터"는 분석 요청에 함께 넣는 예시 자료를 뜻한다. 모델 가중치를 재학습하거나 파인튜닝하지 않으며, 분석 결과의 정확도를 보장하지 않는다.

재고 수량의 출처, 입출고 장부와 PostgreSQL 저장 방식은 [재고 데이터 수집 및 저장 안내](재고_데이터_수집_및_저장.md)를 참고한다. 이 문서의 엑셀 기능은 이미지 레퍼런스용이다.

## 데이터 준비

1. 품목별로 실제 운영 이미지 사용 권한과 촬영 동의를 확인한다. 사람 얼굴, 송장·주소, 계정 정보 등 불필요한 개인정보는 촬영하거나 업로드하지 않는다.
2. 품목을 알아볼 수 있도록 포장 전체와 식별 특징이 보이는 사진을 준비한다. 흔들림, 역광, 과도한 압축, 여러 품목이 겹친 사진은 피한다.
3. 파일명은 영문·숫자 중심으로 짧고 중복되지 않게 정한다. 예: `mackerel-box-01.jpg`.
4. 동일 품목의 다른 포장·각도 이미지는 별도 행으로 등록하고, `description`에 구분 특징을 기록한다.
5. 사진은 앱에서 긴 변 최대 640px, JPEG 품질 65%로 압축된다. 등록용 data URL은 50,000자 이하여야 한다.

## 엑셀 양식

화면의 모니터링 페이지에서 **분석용 레퍼런스 등록 → 엑셀 양식 다운로드**를 선택한다. 첫 번째 시트에 다음 열을 유지한다.

| 열 이름 | 필수 | 내용 |
|---|---|---|
| `name` | 예 | 분석 결과와 연결할 품목명. 실제 재고 품목명과 동일하게 작성 권장 |
| `description` | 아니요 | 색상, 포장, 크기 등 시각적 식별 특징 |
| `imageFile` | 예 | 함께 선택할 이미지 파일의 정확한 파일명 |

각 행에는 품목 이미지 하나를 대응시킨다. 사진 파일은 엑셀 셀에 삽입하지 않고 별도로 선택하며, `imageFile`에는 파일명과 확장자를 포함한다. 파일명은 대소문자를 구분하지 않는다.

### 내보낸 워크북 다시 가져오기

앱에서 **엑셀로 내보내기**를 선택하면 각 행에 `imageDataPart1`, `imageDataPart2` 열이 포함된다. 이 워크북은 이미지 데이터도 포함하므로 별도 이미지 선택 없이 그대로 다시 가져올 수 있다. 열 이름이나 셀 내용을 수정하면 해당 이미지가 손상될 수 있다.

## 일괄 등록

1. 관리자 또는 승인된 창고지기로 로그인한다.
2. 모니터 페이지에서 레퍼런스 등록 창을 연다.
3. `.xlsx` 또는 `.xls` 파일을 선택한다.
4. 양식에서 `imageFile`을 사용했다면 해당 사진들을 함께 선택한다. 내보낸 워크북은 이미지를 포함하므로 사진 선택을 생략할 수 있다.
5. **엑셀 데이터 일괄 등록**을 실행한다.
6. 완료 건수와 화면의 레퍼런스 목록을 확인한다.

한 번에 최대 500행까지 선택할 수 있지만 요청 전체 크기는 20MB 이하, 이미지 하나는 50,000자 이하여야 한다. 한 행이라도 품목명·이미지가 없거나 파일을 찾을 수 없으면 요청 전체를 취소하고 데이터베이스에 일부만 저장하지 않는다. 용량이 크면 행을 나눠 등록한다.

## 목록 확인 및 내보내기

레퍼런스 목록은 현재 로그인한 창고 데이터만 표시한다. 썸네일, 품목명, 설명 또는 등록일을 확인하고 필요 없는 행은 삭제할 수 있다. 다운로드 버튼은 현재 창고의 전체 레퍼런스를 `wms-reference-data.xlsx`로 저장한다. 내보낸 파일에는 품목명, 설명, 등록일과 복원용 이미지 데이터가 포함된다.

## 데이터 품질 및 운영 주의

- 가능하면 같은 품목의 서로 다른 촬영 조건을 여러 건 모으되, 품목명이 혼동되는 라벨을 섞지 않는다.
- 실제 재고 수량을 학습시키는 데이터셋은 현재 저장하지 않는다. 추론 결과의 `estimatedQuantity`는 현장 확인 후 재고에 반영해야 한다.
- 현재 분석 요청은 최근 레퍼런스 최대 3개를 참고한다. 등록 건수가 많아도 매번 전체 이미지가 모델에 전달되는 것은 아니다.
- 이미지 data URL은 PostgreSQL 텍스트 컬럼에 저장된다. 용량·보존기간·백업과 삭제 요청 절차를 운영자가 관리한다.
- 데이터의 출처, 수집일, 수집 담당자, 품목 라벨, 사용 권한을 별도 관리 기록으로 남긴다. 민감하거나 제3자 권리가 불명확한 데이터는 등록하지 않는다.
- 정답 라벨을 보유하더라도 정확도 검증 전에는 AI confidence를 정확도나 재고 실측값으로 간주하지 않는다.

## 현재 한계

- 레퍼런스 등록은 검색 문맥에 참고 이미지를 제공하는 방식이지 모델 재학습·파인튜닝이 아니다.
- 이미지 분석에는 `GROQ_API_KEY`와 해당 모델 사용 권한이 필요하다.
- 내보내기 워크북은 큰 이미지 데이터가 포함되면 파일 크기가 커질 수 있다. 사내 승인 저장소에 보관하고 접근 권한을 제한한다.
- 브라우저의 카메라 권한, IP 카메라의 CORS·코덱 지원, 네트워크 상태에 따라 실시간 분석이 동작하지 않을 수 있다.
