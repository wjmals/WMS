# SmartStock AI WMS

창고별 재고, 구역, 배송, 이미지 모니터링을 한 곳에서 관리하는 웹 앱이에요. 재고 데이터는 Rust API와 PostgreSQL에 저장돼요.

## 설치

사전 조건: Docker, Node.js/npm, Rust/Cargo가 필요해요.

1. 프런트엔드 의존성을 설치해 주세요.

   ```bash
   cd frontend && npm install && cd ..
   ```

2. PostgreSQL을 켜 주세요. 기존 DB는 Rust API가 시작할 때 필요한 컬럼과 테이블을 자동으로 추가해요.

   ```bash
   docker compose up -d postgres
   ```

3. Rust API를 별도 터미널에서 실행해 주세요.

   ```bash
   cd rust-backend
   DATABASE_URL=postgres://wms:wms_password@localhost:5432/wms cargo run
   ```

4. 저장소 루트에서 프런트엔드를 실행하고 `http://localhost:3000`에 접속해 주세요.

   ```bash
   npm run dev
   ```

휴대폰에서 카메라 스캔을 쓰려면 HTTPS 주소 또는 `localhost`로 접속해야 해요.

## 사용법

- 회원가입 후 창고 관리자가 승인하면 로그인할 수 있어요. 역할은 서버 관리자, 창고 관리자, 창고지기예요.
- 상단 탭(바코드 스캔, 배송 관리, 재고 현황, AI 리포트, 실시간 모니터링)에서 현재 화면이 강조돼요.
- **바코드 스캔**: 카메라, USB/블루투스 바코드 리더기, 직접 입력으로 품목을 찾아요. `스캔 시 동작`을 `스캔마다 입고/출고`로 바꾸면 인식할 때마다 입력한 수량만큼 바로 처리돼요. 기본값은 `품목만 선택`이에요.
- **수량 입력**: 입력 단위를 따로 고를 수 있어요(ea, 박스, 파렛트). 선택한 단위는 등록된 환산값으로 ea로 계산돼요.
- **재고 현황**: 품목별 현재 재고, 구역별 보관량, 최근 30일 입고·출고·기타 조정 막대 그래프를 볼 수 있어요.
- **AI 리포트**: `재고 부족 / 안전 재고 / 재고 과다 / 안전재고 미설정` 카테고리를 누르면 해당 품목만 보여요.
- **배송 관리**: 같은 창고 배송을 등록하고 tracker.delivery로 실시간 조회해요. 완료 24시간 뒤에는 목록에서 빠져요.
- **실시간 모니터링**: 이미지를 Groq Vision으로 분석해요. 결과는 관리자가 승인한 뒤에만 재고에 반영돼요.

## 설정

### 품목과 단위

- 기본 단위는 `ea`예요. 품목마다 박스 단위(박스당 ea 수)와 파렛트 단위(파렛트당 ea 수)를 따로 지정할 수 있어요.
- 재고 수량은 소수점 둘째 자리까지 보여줘요. 내부 저장 정밀도는 그대로예요.
- 품목을 삭제하면 보관 처리돼요. 남은 수량은 `기타 조정`으로 장부에 남고, 구역 배치 목록에서도 사라져요.

### 안전재고

- 수동으로 정하거나 출고 이력으로 자동 계산할 수 있어요. 자동 계산은 학습형 AI가 아니라 통계식이에요.

  $$안전재고 = Z \times \sigma_{최근\ 28일\ 일별\ 출고량} \times \sqrt{리드타임\ 일수}$$

- 기본 서비스 수준은 95%(`Z=1.645`), 리드타임은 7일이에요.
- 완료일 35일 이상, 최근 28일 중 출고일 5일 이상이어야 계산돼요. 엑셀로 가져온 이력은 **승인된 뒤에** 이 계산에 포함돼요.
- 안전재고가 0인 품목은 `안전재고 미설정`으로 따로 표시되고, 값을 저장하면 목록에서 사라져요.

### 과거 거래 엑셀 가져오기

1. AI 리포트 아래 `엑셀 양식`을 내려받아 `거래입력` 시트에 적어 주세요. `품목목록`(참고용)과 `작성방법` 시트가 함께 들어 있어요.
2. 열은 `거래일시 / 품목명 / 바코드 / 유형 / 수량 / 단위 / 사유 / 참조번호`예요. 유형은 목록에서 `기초재고, 입고, 출고, 조정, 비전추정` 중에 골라요.
3. 신규 품목은 `기초재고` 행을 한 줄 먼저 넣어 주세요. 입고·출고는 양수, 조정·비전추정은 부호 그대로 적어요.
4. `승인 요청`을 누르면 신규 품목과 거래가 모두 **승인 대기**로 등록돼요. 창고 관리자가 승인해야 재고와 장부에 반영되고, 반려하면 아무것도 반영되지 않아요.
5. 비전추정 행도 조정과 같은 방식으로 반영돼요(장부에는 `비전추정`으로 남아요).

### 재고 변동 기록

- 재고 현황 하단의 장부에서 품목, 담당자(검색 또는 목록 선택), 출처, 유형으로 걸러볼 수 있어요.
- `전체 기록 엑셀 저장`(필터를 쓰면 `필터 결과 엑셀 저장`)으로 입고·출고 기록을 엑셀로 받을 수 있어요. 최대 20,000건이에요.

## 기술 구성

```text
Browser -> Next.js frontend -> Rust Axum API -> PostgreSQL
                                             -> Groq Vision (모니터 분석)
```

- `frontend/`: Next.js 16, React 19, TypeScript
- `rust-backend/`: Axum, SQLx, PostgreSQL 16
- `admin_console/`, `cv_client/`: 별도 Python 도구

주요 코드 위치는 `frontend/app/`(화면, API 프록시), `rust-backend/src/main.rs`(API와 로직), `rust-backend/schema.sql`(DB 정의)이에요. API 요청·응답은 [API 명세서](docs/API_명세서.md)에서 볼 수 있어요.

## 직접 빌드

```bash
cd rust-backend && cargo check
cd ../frontend && npx tsc --noEmit && npm run build
```

배포는 프런트엔드를 Vercel, API와 DB를 Render에 올려요(`vercel.json`, `render.yaml`). 비밀 값은 호스팅 secret store에서 관리해 주세요.
