# SmartStock AI WMS

창고의 재고와 입출고, 배송을 한곳에서 관리하는 웹 앱이에요. 화면은 Next.js로, API 서버는 Rust로 만들었고 데이터는 PostgreSQL에 저장해요.

## 할 수 있는 일

- 회원가입 후 창고 관리자 승인을 받아 사용할 수 있어요. 사용자 역할은 서버 관리자, 창고 관리자, 창고지기예요.
- 재고를 등록하고 입고·출고·조정 내역을 확인할 수 있어요. 품목별 일반 목록, 카드 히트맵, 격자 히트맵 보기와 검색도 지원해요.
- 품목별 기본 단위와 박스·파렛트 환산 단위를 설정할 수 있어요.
- 카메라, 키보드형 바코드 리더기, 직접 입력으로 품목을 찾을 수 있어요.
- 과거 거래 엑셀을 한 번에 1~50,000행까지 가져올 수 있어요. 가져온 거래와 신규 품목은 검토·승인 후 반영돼요.
- 품목별 입출고 이력, 월별 출고량, 전체 거래 내역을 확인하고 엑셀로 저장할 수 있어요.
- 같은 창고의 배송을 관리하고 tracker.delivery로 운송장 진행 상황을 조회할 수 있어요.
- 구역별 보관량과 공실률을 확인할 수 있어요.

## 재고 상태는 이렇게 정해요

현재 수량을 안전재고와 비교해 상태를 표시해요.

- 안전재고가 0 이하이면 `안전재고 미설정`이에요.
- 현재 수량이 안전재고의 50%보다 적으면 `재고 부족`이에요.
- 현재 수량이 안전재고의 50% 이상이고 200% 이하이면 `안전 재고`예요.
- 현재 수량이 안전재고의 200%보다 많으면 `재고 과다`예요.

격자 히트맵은 같은 수량을 더 알아보기 쉽도록 안전재고 대비 비율별로 색칠해요. 타일에 마우스를 올리면 품목명, 현재 수량, 안전재고를 볼 수 있어요.

안전재고는 직접 설정하거나 출고 이력으로 자동 계산할 수 있어요. 자동 계산은 AI가 아니라 통계식이에요.

`안전재고 = Z × 최근 최대 180일 일별 출고량의 표준편차 × √리드타임(일)`

기본 서비스 수준은 95%(Z=1.645), 기본 리드타임은 7일이에요. 계산에는 완료일 이력이 35일 이상이고 최근 180일 중 출고가 있었던 날이 5일 이상이어야 해요. 조건이 부족하면 자동 계산으로 전환할 수 없어요.

## 수요 예측에 대해

예측 화면과 API는 1일·7일·30일 출고량을 제공해요. **현재 실제 예측값은 최근 28일의 일평균 출고량을 바탕으로 계산해요.** API 코드에는 Random Forest 백테스트 계산도 있지만, 실제 화면에 제공하는 예측값을 학습형 AI 결과라고 보면 안 돼요. WAPE 등의 비교 결과도 예측 정확도를 보장하지 않아요.

품절률과 제때 출고된 비율은 아직 계산할 수 없어요. 미충족 주문과 약속 출고 시각을 기록하지 않기 때문이에요.

## 실행 방법

필요한 도구는 Docker, Node.js/npm, Rust/Cargo예요.

1. 프런트엔드 패키지를 설치해 주세요.

   ```bash
   cd frontend
   npm install
   cd ..
   ```

2. PostgreSQL을 실행해 주세요.

   ```bash
   docker compose up -d postgres
   ```

3. Rust API를 실행해 주세요.

   ```bash
   cd rust-backend
   DATABASE_URL=postgres://wms:wms_password@localhost:5432/wms cargo run
   ```

4. 저장소 루트에서 프런트엔드를 실행해 주세요.

   ```bash
   npm run dev
   ```

5. `http://localhost:3000`을 열어 주세요.

기존 DB 데이터를 지우는 명령은 실행하지 마세요. 특히 `docker compose down -v`는 데이터 볼륨까지 삭제할 수 있어요.

## 배포 설정

Vercel에는 Next.js 프런트엔드를 배포하고, Render에는 Rust API를 배포해요. PostgreSQL은 Neon 같은 관리형 DB를 사용할 수 있어요.

- Vercel의 `RUST_API_URL`에는 Rust API의 HTTPS 주소를 설정해 주세요.
- Render의 `DATABASE_URL`에는 사용할 PostgreSQL 주소를 설정해 주세요.
- `JWT_SECRET`, `SUPER_ADMIN_PASSWORD`, `FRONTEND_ORIGINS`는 호스팅 서비스의 비밀 환경변수로 관리해 주세요. 실제 비밀값을 코드나 README에 적지 마세요.
- DB 연결을 바꿀 때는 서비스가 새 주소로 배포됐는지와 `/health` 응답을 확인해 주세요.
